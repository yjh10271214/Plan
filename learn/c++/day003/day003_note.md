## vector 的动态扩容
> - vector 底层是一个连续内存的动态数组，通过三个指针管理：_start、_finish、_end_of_storage。
> - size() 是已有元素个数，capacity() 是已分配内存能容纳的元素个数。
> - 当 size() == capacity() 时，push_back 会触发扩容：
>   1. 分配一块更大的新内存（通常为原容量的 1.5 或 2 倍）。
>   2. 将原有元素拷贝/移动到新内存。
>   3. 释放旧内存。
>   4. 更新内部指针。
> - 按倍数扩容是为了保证 均摊时间复杂度 O(1)。若每次只扩固定大小，会退化为 O(n²)。
> - 扩容因子：GCC 下通常为 2，MSVC 通常为 1.5。

## 迭代器失效
> - 扩容会释放旧内存、分配新内存，因此扩容前获取的所有迭代器、指针、引用全部失效。
> - 使用失效的迭代器是未定义行为，可能崩溃、乱码或“看似正常”，排查困难。
> - 避免方法：
>   - 提前用 reserve() 预分配足够容量，避免中途扩容。
>   - 扩容后重新获取迭代器，不要缓存旧的。

## 如何真正释放 vector 占用的内存
> - clear() 只会清空元素（size 变 0），capacity 不变，内存未释放。
> - C++11 引入 shrink_to_fit()，但不保证一定释放。
> - 最可靠的方法：vector<int>().swap(v); 用空的临时 vector 交换，临时对象析构时带走原内存。

## map / set 的红黑树
> - map 和 set 底层通常是红黑树（自平衡二叉搜索树）。
> - 插入、删除、查找复杂度均为 O(log n)，且元素按键有序。
> - 有序的原因：中序遍历二叉搜索树即得有序序列。
> - O(log n) 的原因：红黑树通过旋转和颜色规则保证树高始终为 log(n) 级别。
> - 与 unordered_map/unordered_set 的区别：后者基于哈希表，O(1) 但无序。
> - 可以自定义排序规则：传入函数对象或 lambda 作为比较器。

## lambda 表达式
> - 本质：编译器自动生成的匿名函数对象（functor）。
> - 结构：[capture](parameters) -> return_type { body }
>   - [=]：值捕获；[&]：引用捕获；[]：不捕获。
>   - 参数、返回类型、函数体与普通函数类似。
> - 常用于 sort、for_each 等 STL 算法中自定义行为，或为 map 提供自定义排序规则。
> - 当 lambda 不捕获任何变量时，可以隐式转换为函数指针。

## 迭代器的五层体系
> - C++ 标准定义了五种迭代器，能力从弱到强：
>   1. 输入迭代器：只读，++it，单次遍历（如文件流）。
>   2. 输出迭代器：只写，++it，单次遍历。
>   3. 前向迭代器：可读写，++it，可多次遍历（如 forward_list）。
>   4. 双向迭代器：支持 ++it 和 --it（如 list、map、set）。
>   5. 随机访问迭代器：支持 it + n、it[n]、大小比较（如 vector、deque、原生指针）。
>  - 面试常考：vector 是随机访问迭代器，map/set/list 是双向迭代器，因此 map 的迭代器不支持 it + 1。

## 常见容器的迭代器失效规则
> - 连续内存容器（vector、deque）扩容或中间插入/删除时，容易大范围失效。
> - 节点型容器（list、map、set）插入时迭代器永不失效，删除时仅被删元素的迭代器失效。
> - 具体规则：
>   - vector：扩容 → 全部失效；insert/erase → 操作位置及之后全部失效。
>   - list：insert → 永不失效；erase → 仅被删元素失效。
>   - map/set：insert → 永不失效；erase → 仅被删元素失效。

## std::function
> - 一个万能的可调用对象包装器，只要调用签名匹配，可以装普通函数、lambda、函数对象。
> - 内部使用类型擦除技术实现，通常会在堆上分配内存来存储可调用对象。
> - 调用时有一层间接跳转，性能略低于直接调用，但换来了极大的灵活性。
> - 典型用法：std::function<int(int, int)> 可以装任何接收两个 int、返回 int 的可调用物。

## 多线程基础
> - std::thread：创建线程，传入可调用对象和参数，线程立即启动。
> - join()：等待线程结束；若不调用且不 detach()，线程析构会终止程序。
> - std::mutex：互斥锁，保证同一时刻只有一个线程访问共享数据。
> - std::lock_guard：RAII 风格的锁管理，构造加锁、析构解锁，不会漏锁。
> - 死锁：两个线程互相等待对方持有的锁，程序卡死。避免方法：
>   - 按相同顺序加锁。
>   - 使用 std::lock 同时锁住多个 mutex。
> - 数据竞争：多线程无同步地读写同一变量，是未定义行为。

## 条件变量与生产者-消费者模型
> - 条件变量 std::condition_variable 用于线程间的等待与通知，常搭配互斥锁和共享队列。
> - 核心操作：
>   - wait(unique_lock, predicate)：原子地释放锁、进入等待；被唤醒后重新获取锁，并检查条件。
>   - notify_one() / notify_all()：叫醒等待的线程。
> - 生产者-消费者模型：
>   - 生产者：生产数据放入缓冲区，若缓冲区满则等待；放入后通知消费者。
>   - 消费者：从缓冲区取出数据，若缓冲区空则等待；取出后通知生产者。
> - 必须用 unique_lock 而非 lock_guard，因为 wait 需要临时解锁。
> - 必须用带谓词的 wait 或 while 循环检查条件，防止虚假唤醒。

## others
> - std::vector<bool> 是特化版本，内部用 bit 而非 byte 存储，不满足连续容器要求，使用时需注意。
> - reserve() 只改变 capacity，不改变 size；resize() 同时改变 size 和 capacity。
> - map 的迭代器是双向迭代器，不支持随机访问（it + 1 不可用），遍历只能 ++it
> - 迭代器的能力由底层数据结构决定：连续内存支持随机访问，链表/树只能双向或前向遍历。
> - std::function 是现代 C++ 中实现回调、策略模式、事件处理的核心工具。
> - 类型擦除不仅用于 std::function，也是 std::any、std::shared_ptr 的 deleter 等机制的基础。
